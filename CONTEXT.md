# Social Media Analysis Agent

A GCP-based system that ingests ad creatives, extracts structured creative
features from each image, mines which feature patterns correlate with
performance, and **critiques a user's own ad** against those patterns. This file
is the glossary — the canonical language for the domain.

> Supersedes the retired "Media AI Platform" (a LiteLLM/Supabase copy-generation
> product). See [ADR-005](./docs/adr/ADR-005-supersede-media-ai-platform.md).

## Language

**Ad Creative**:
A single advertisement image under analysis. Identified by an `ad_id`.
_Avoid_: Asset, image, ad (when precision matters), banner.

**Extraction**:
The Step 2 process that turns one Ad Creative into a structured feature
document. Produces creative features only — never a performance metric.
_Avoid_: Analysis, processing, parsing.

**Extraction Result**:
The structured document Extraction produces for one Ad Creative — the frozen
Master JSON Schema that downstream steps consume.
_Avoid_: Output, payload, JSON blob.

**Creative Feature**:
Any attribute extracted from an Ad Creative (colour palette, hook framework,
human presence, typography hierarchy, etc.). Deliberately separate from
performance — features describe the creative, never how it did.
_Avoid_: Signal (reserve that for Step 3), attribute, property.

**Performance**:
How well an ad did. With no ROAS, v1 Performance is a **composite proxy** built
only from Meta Ad Library signals: **Longevity** as the base, **weighted by**
brand **Scaling**, and boosted by **Variant** count. Engagement (likes/shares) is
*not* exposed by the Ad Library and is excluded. ROAS is a Phase-2 concept.
Performance joins to Creative Features in Step 3, never inside Extraction.
_Avoid_: Score, success, results.

**Longevity** (`days_active`):
The base of the v1 Performance proxy: how many days a competitor ad has run
without being paused. A long run *suggests* profitability — but it is
correlational and confounded (big brands keep ads running regardless), which is
why it is weighted by Scaling rather than trusted alone.
_Avoid_: Duration, age, lifespan.

**Scaling**:
A brand-level signal — how many ads a brand currently has active. Used to weight
Longevity so a *lone* long-running ad is discounted while a brand running *many*
ads counts as scaling (a stronger success signal). Computed per brand (page), so
the scrape must capture *all* of a brand's active ads.
_Avoid_: Volume, spend (we have neither), reach.

**Variant**:
A distinct active creative version of one ad. A higher active-variant count means
the advertiser is actively testing/investing in that ad — a secondary boost to
its Performance proxy.
_Avoid_: Version, A/B, duplicate.

**ROAS**:
Return on ad spend — exact performance truth from your own Meta account. A
**Phase-2** concept; there is zero ROAS data today, so v1 must never emit or
display a ROAS figure.
_Avoid_: Return, profit, performance (when you specifically mean ROAS).

**Cognitive Layer**:
The Extraction stage that uses Gemini for features needing genuine
understanding (objects, spatial relationships, human micro-detail, marketing
psychology). Everything structural (dimensions, colour, OCR geometry) stays
deterministic and never touches an LLM.
_Avoid_: AI stage, LLM step, inference.

**Deterministic Stage**:
An Extraction stage computed with code/math alone (metadata, OCR geometry,
K-Means colour) — reproducible and free. The opposite of the Cognitive Layer.
_Avoid_: Local stage, offline stage.

**Stage**:
One pluggable unit of the Extraction pipeline implementing `BaseStage.process`,
mutating a `PipelineContext`. Numbered 1–6; Stage 4 (verification) is deferred.
_Avoid_: Step (reserve "Step" for the five top-level pipeline phases).

**Step**:
One of the five top-level pipeline phases: 1 Ingestion · 2 Extraction ·
3 Pattern Discovery · 4 Fine-Tuning · 5 UI. Distinct from a Stage, which lives
*inside* Step 2.
_Avoid_: Phase, module.

**Pattern**:
A combination of Creative Features shown by Step 3 to correlate with
Performance (e.g. PAS hook + Studio background + human model → high Longevity).
Patterns are derived statistically, not generated by an LLM.
_Avoid_: Insight, rule, recommendation.

**Corpus**:
The set of scraped competitor Ad Creatives that Patterns are mined from.
Extracted *cheaply* (Deterministic Stages + Gemini on the flat image) — never
with Layer Decomposition.
_Avoid_: Dataset, training set, ad library.

## Critique & Generation

**Critique**:
The v1 user-facing product. Takes a user's *own* Ad Creative, extracts its
features (including Layer Decomposition + Composition), compares them against the
top Patterns for its Product Type, and returns Suggestions. It analyses an
existing ad — it does not create one (that is Generation).
_Avoid_: Review, audit, analysis (when you mean this specific product).

**Suggestion**:
A single piece of Critique feedback. Two kinds, always labelled by which:
*benchmarked* (grounded in Corpus Patterns for the Product Type) and
*best-practice* (design-principle / VLM judgement, not yet Corpus-proven —
typically Composition feedback).
_Avoid_: Recommendation, tip, fix.

**Layer Decomposition**:
Splitting a flat Ad Creative into RGBA layers (background, product, text)
via Qwen-Image-Layered, so colour maths and the Cognitive Layer can analyse each
layer and their Composition. As of [ADR-008](./docs/adr/ADR-008-layered-color-vlm-imagery-retrieval-embeddings.md)
it runs on **all ads (corpus + user)** — amending ADR-007, which reserved it for
the user's Critique ad only. Inpainted/hallucinated background pixels are never
treated as extraction evidence (colour is sampled from real layer pixels).
_Avoid_: Segmentation, masking, layering.

**Composition**:
How an Ad Creative's layers interact — z-order and overlap (e.g. copy rendered
on top of the product). Distinct from typography hierarchy (within text) and
object relationships (between objects in one scene).
_Avoid_: Layout, arrangement, structure.

**Generation** (a.k.a. Ideal Ad):
The post-v1 product that synthesizes a new ad from a client's raw product
photo + stated intention, grounded in real top-performing Corpus ads
(retrieval) and Cox/SHAP-derived visual directives. Built mechanism (as of
Wayfinder Map #36, Round 6): a masked background inpaint — a background-
removal model produces an alpha matte of the product, which becomes an
Inpaint Mask so a fill model (Flux Fill Pro) regenerates only the
surrounding scene while the product's own pixels — including its label
text — are never touched — composed with Gemini-driven copy/style-brief/
layout/review agents and deterministic code-rendered text/CTA elements.
Does *not* use Qwen Layer Decomposition for this path (that mechanism is
reserved for Critique). Deliberately fenced off from Critique's extraction
evidence so generated pixels never contaminate analysis.
_Avoid_: Reconstruction, rendering, the brief generator (that was the retired
design), Qwen layers (not used on this path).

**Inpaint Mask**:
A black-and-white image marking which pixels a diffusion fill model may
regenerate (white) versus must preserve verbatim (black) — Generation's
mechanism for protecting the product photo's own pixels from being
re-rendered (and, historically, garbled) by a whole-image edit model. A
different, unrelated technique from Layer Decomposition's RGBA layer
splitting, despite Layer Decomposition's own entry listing "masking" as a
term to avoid for *that* concept — the two share an English word, not a
mechanism.
_Avoid_: Segmentation (that term is reserved for Layer Decomposition's own
avoid-list, for the same reason spelled out above).

**Product Type**:
The normalized category of the product an Ad Creative sells — the **join key**
between a user's ad and the Patterns it is critiqued against. Drawn from a fixed,
curated taxonomy (~15–30 coarse top-level types) kept in config; Gemini
classifies every Ad Creative (corpus and user) into it during the cheap cognitive
stage. The raw product name is retained alongside for future sub-typing. Coarse
on purpose, so each type has enough Corpus ads to mine stable Patterns.
_Avoid_: Category, vertical, niche, inferred_category.
