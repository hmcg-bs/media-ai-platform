# 2026-09-12 — Meta Ads feature model and training pipeline

## Goal

Align Step 3 with the documented competitor-ad Performance proxy and make
Step 1/feature-matrix/training jobs resumable, reproducible, and safe to run
concurrently on distinct outputs.

## Decisions

- Performance is a bounded rank-based composite: 70% Longevity, 20%
  Longevity×page-level Scaling, and a 10% Meta collation Variant boost.
- Landing-page SKU/bundle count is a feature, not a Performance ingredient.
- Composite attribution uses advertiser-group holdout; component CV preserves
  time order. Target-derived cluster trend features were removed from the CLI
  because each training row contributed to its own encoded outcome.
- Same-output jobs fail fast under an advisory lock; checkpoints publish by
  atomic rename. XGBoost defaults to one worker per job.

## Changed

- Hardened Apify search URL construction and resumable multi-query ingestion.
- Added page-level Scaling, extraction-availability features, numeric
  missingness indicators, active-ad censoring, baseline/ranking metrics, input
  hashes, and composite SHAP attribution to the training report.
- Added `docs/meta-ads-training-pipeline.md` and updated project/domain pointers.
